# 网络排查顺序

1. 确认本地代理已启动、端口正确。只开启代理软件而没有启用系统代理，也没有使用 explicit 模式时，原生程序可能仍然走直连。
2. 运行 Diagnose。`transport_error` 表示 DNS、TCP、TLS、代理或超时层面的失败；查看 curl 错误码。工具始终验证证书。
3. `401/403` 归为 `auth_or_policy_required`。它们说明收到了服务响应，但不能证明账户认证、地区、工作空间策略或浏览器挑战已通过。`404/426` 也不是 Dot 工作成功的证据。
4. 完全退出应用后用本工具启动。已有进程保持原启动环境；再次运行启动器只能打开现有窗口。
5. 确认同一账户与工作空间、Dot 本机访问授权、电脑在线且应用保持运行。
6. 只提交一次无副作用的文件读取测试。若创建对话请求超时，先查现有会话列表／活动，避免重复提交。

HTTP 可达、WebSocket 握手成功、已认证的长连接稳定、桌面接口可用、任务执行成功，是不同的验收层次。当前诊断仅覆盖第一层；没有认证材料就不会尝试伪造其余层的成功结果。

代理模式建议：

| 使用环境 | 起点 |
| --- | --- |
| Clash／其他客户端提供 HTTP 端口，TUN 关闭 | auto 或 explicit；应用进程需使用代理 |
| TUN 或全隧道 VPN 已覆盖相关进程 | direct 模式测试系统路由，结合 VPN 自身规则验证 |
| PAC／按应用分流 | explicit 指定 HTTP 代理，或由网络管理员确认应用路由 |
| 服务端 401／403／设备授权失败 | 检查账户与策略，单纯多次重连可能无效 |

不要把桌面 app-server 暴露到公网来绕开问题，不要为此关闭证书校验、身份验证或防火墙。网络路由可用不代表已获得对工作空间或本机的访问授权。

参考：[Dot 电脑连接](https://learn.chatgpt.com/docs/dots/computers-and-apps)、[远程连接](https://learn.chatgpt.com/docs/remote-connections)。
